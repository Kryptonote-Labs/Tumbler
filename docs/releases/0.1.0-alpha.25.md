# 0.1.0-alpha.25

All nine public `@tumblerjs` packages use this version and publish under `latest`.

## Word APIs

- Import existing DOCX into `NativeWordDocument`, project editable content with `importWordContent`, and preserve source references through export. `createWordSourceManifest` provides immutable provenance for host validation.
- Use the optional `@tumblerjs/word/collaboration` entry point for anchored text, formatting, image, and table operations. Yjs remains optional for the native engine.
- Edit shared headers and footers or section variants with `updateStory`. Author live `PAGE` and `NUMPAGES` fields with `wordPageNumberRuns` and import supported complex page fields.
- Format table cells, borders, row heights, and column widths. Continue long rows across pages while retaining repeated headers, cell margins, and border spacing.
- Use paragraph positioning, positional tabs, vertical caret navigation, click-and-type intent, and composed page-number editing APIs.
- Reuse native paragraph/table geometry and incremental collaboration projections. Keep exports at file boundaries rather than rebuilding DOCX for each edit.

## Correctness

- Improve paragraph line metrics, list indentation, aligned tabs, trailing-space wrapping, negative table indentation, and page continuation.
- Retain image media identity across geometry edits and expose reusable Svelte drawing controls.

## Documentation

The public site now includes Word authoring and collaboration guides, native import examples, and a feature-specific Word compatibility matrix. Package and implementation documentation no longer describe removed authoring caps or list supported story/page-field/table APIs as absent.

## Publishing

Qualify the clean release commit against an installed Kryptonote checkout, push the qualified commit to `origin/main`, and publish pending packages in dependency order:

```sh
bun run release:qualify /path/to/Kn
bun run release:next
bun run release:publish
```

Repeat the publisher until all nine packages are present. Every publish uses `latest`; existing versions are skipped. Build and deploy the docs from the released source after publication.
